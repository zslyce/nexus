## Notes from wave 1
- Session rules: `MANDATORY_SESSION_RULES` in `src/contracts/security.ts`, appended after any other session rule. Omit the `.env.example` allow for an agent without `read`.
- Normalizer: build it with `workspace` and `validationCommandPatterns`; route with `sessionIdOf` and drop unowned sessions; `restore` each non-terminal task after a restart; `forget` when an attempt ends. Bus delivery is asynchronous. The `permission_asked` signal carries at most 5 resources.
- Store: rules in docs/03; insert batches in dependency order inside one transaction; append `TASK_CREATED` after `insertTask`; pass the agent snapshot to `insertTask`. `TASK_*` payloads are not sanitized by the store.
- Resolve batch keys to task IDs and the effective model string before `deriveIdempotencyKey`. IDs, backoff and error classification come from `src/utils`.
- Gateway: `getOutput().error` carries `transient` and `status`; `subscribe` is global.
- Observed (docs/04, "Tools"): rejecting a permission ends the run as interrupted (reason `shutdown`, no `outcome`). End that task as `failed` with the rejected permission in `errors`; never treat it as a user cancel or resend the prompt during recovery.
- `getDiff` can be empty although files changed: complete `filesModified` from the `FILE_MODIFIED` events.
- A denied tool call still advances the stage to `execution` (stage comes from `tool.called`): cosmetic, raise it if it misleads.

Parallelism and global/per-agent limits; dependencies and cascading failure; cycles rejected; file conflicts; cancel in every state, including the race with completion; timeout; retry only when ADR-012 allows it; duplicate delegation; every row of the recovery table in 03; SSE drop with a task that finishes while disconnected; events from other sessions ignored.
